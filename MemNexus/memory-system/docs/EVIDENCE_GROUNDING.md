# 原文读取单元、证据预算与来源核验：设计和验证

实现说明更新：2026-11-24。下方保留的数值实验属于 2026-10-12 的历史验证，不代表当前版本成绩。最新修改、固定规划回放、原生 QA 配对与失败版本均独立保存在仓库 result/evidence_chain_20261124；阅读验收和答案质量验收分开，不用原文可见性代替 Accuracy/F1。

## 研究假设和完成标准

早期 100 题实验中 MemNexus 为 65/100，SimpleMem 为 82/100；这是历史结果，不是当前双系统对比。多道错题已检到相关记忆，却因缺少来源日期、主体信息或必要细节而拒答。当前检验的假设是：压缩表示适合定位信息，回答应从原始来源恢复完整关系和必要上下文，并在相同预算内保留这些信息。

四个问题分别对应可验收的目标：

| 问题 | 代码目标 | 验收范围 |
|---|---|---|
| 时间推算不足 | 从来源时间推导带精度的日期区间 | 闰年、跨年、月份、周末、星期、时区边界、有歧义表达不造日期 |
| 有证据仍拒答 | 将来源和可复验推导传入生成器，区分缺证据与需要推导 | 历史同输入模型组件对照；当前来源回放不能替代完整 QA 验收 |
| 证据覆盖不全 | 压缩记忆与原文候选合并，先构建读取单元，再按同一序列化预算选择 | 固定原生规划、同一快照的离线来源回放；不将检索命中当作新答案得分 |
| 压缩或归属损失 | 原始文本可恢复；时间、说话者由源事件给出；冲突时回到原文 | 混合陈述/问句、主体错配、原文缺失细节、跨会话和撤回边界 |

这不是对所有数据集的正确性保证。日期语言理解、指代消解和最终生成仍有无法由单元测试证明的语义误差；必须保留独立 QA 验证这一关。

## 表示与推理边界

### 单一答案链与来源契约

直接问答沿用 `检索 → 原文组装 → source_bound_synthesis → 来源与输出契约校验 → 渲染`。查询计划描述所需信息、主体和时间条件，结构化抽取字段帮助定位，均不能替代来源事实。复杂问题的 `recall_first` 使用既有召回策略，不增加模型分类调用，也不绕过作用域和生命周期。

复用 `Candidate.content` 保存自包含重述，保留主体、关系、数量、否定、条件及原文明示的列表顺序；`semantics.members` 保存逐项答案值及其证据。两者属于同一记忆对象，没有新增第二份重述 schema。原始 `Event` 保留完整文本，重述遗漏的细节可在权限允许时读回，不能从 `summary` 补造事实。

来源不足不自动等于全历史中不存在答案。直接问答由同一次结构化生成绑定原文、回答支持的部分；原文可核对的计算由确定性代码检查。不能把未选中某条候选、词法覆盖不足或缺少固定句型单独作为拒答依据。未实现 `synthesize` 的旧模型适配器和行动方案仍使用 plain-answer 接口；其事件图与 `typed_negative_gate` 是另一既有接口的输入辅助，不是直接问答的新出口。

归属和关系判断保留来源角色：assistant 的历史建议可支持“当时说了什么”，不能直接成为用户经历、偏好或已确认规则。抽取提示不是语义证明；即使引用位置正确，仍需验证最终答案是否正确理解了原文。

`Event` 新增 `speaker` 和 `source_utc_offset_minutes`。原始时间先保留来源 UTC 偏移，再按既有规范储存 UTC 时间。回答阶段重新使用来源当地日历日期，避免 UTC 跨日引入错误。未提供时区的历史数据不能推断时区；导入器必须声明其假设。

服务根据 `Evidence.turn_id/event_index/quote` 回查权威原始 turn。`start/end` 是原始 Unicode 字符串的半开区间，必须满足 `event.content[start:end] == quote`，不使用归一化文本或 UTF-8 字节偏移。抽取模型不计算位置；程序可为唯一逐字匹配填入坐标，重复引文不伪造唯一位置。旧无坐标记录继续可读，父级和成员证据使用同一契约；冻结快照不因加载而被改写。

历史来源通过 `source_session_ids` 指定同 owner、同项目的会话，默认 `source_read_scope="quotes"` 只允许已授权引用范围；显式 `events` 才允许读取这些会话内未被抽取的原始发言。全文读取权限不等于整段放入 prompt，更不授权其他会话。HTTP、流式 HTTP 和 SDK 使用同一规则。授权范围在构建读取单元前确定；语义补检索也只能对本次可读、未撤回的事件建立或读取向量。

基准适配器的新 LME-S 运行显式选择 `events`，授权范围就是该题已提供的完整 history，不使用 gold evidence 筛选会话；LoCoMo 保留当前会话/default `quotes`。这是 QA 协议变更：stage、逐题结果和配对协议记录读取范围，续跑同时核对 scope 与会话 grant，旧 quotes 或无范围标记的 LME 答案不得混入新运行。历史结果仍可只读分析，已有构建快照可在新的 QA 目录复用，但不会把旧答案改标为 events。

压缩记忆中的字段仍是检索提示。对于“原说话者是甲，第一人称原话却被压缩成乙”的可确定冲突，回答上下文使用原文替换争议摘要，并记录 `attribution_conflicts`。不尝试凭词法规则证明所有第三人称或隐含指代正确。

## 时间推导

`temporal.py` 产出半开区间 `[start, end_exclusive)`，保留 `precision` 和来源表达式位置。支持绝对 ISO 日期、today/yesterday/tomorrow、last/this/next 年月周、last weekend、前后指定星期、明确 N 个单位 ago，以及部分中文对应表达。

- “last year”只给年区间，不编造月日。
- “next month”保留月精度；12 月正确跨到下一年。
- “last weekend”采用上一 ISO 周末；“last Saturday”采用严格前一个星期六。这些是显式约定，不声称覆盖全部口语方言。
- “已有三年”没有被强制变成购买/领养日期；需要语义事件关系才能推出具体事件。
- “几天前”、无时间锚点、引语内部可能具有不同参照时间的相对表达不生成确定日期。
- `occurred_at`、入库时间 `recorded_at`、事实有效期 `valid_from/valid_to` 不混用。

每条时间结果只是对来源表达式的日历解释，不自动证明它对应了用户所问事件。

## 完整读取单元与一次预算选择

复用原始向量/FTS/符号检索和现有原文补检索，在同一读取链路内处理：

1. 三路召回的内部候选并集随 `SearchResponse.candidates` 传入回答阶段。公开 search 仍返回原有 `results`；内部候选字段不进入 JSON 或 SDK 公开结果，不扩大访问权限。
2. 核对引用、生命周期及授权范围，恢复原文、时间和说话者。必要时沿用至多一轮原文补检索；输入来自问题与规划需求，不使用 gold answer、gold evidence 或数据集类别。
3. 在选择前构建读取单元：完整原句/段落、带标题的列表或指定列表项，以及权限内必要的邻接会话上下文。原文顺序和位置保留；邻接仅提供理解上下文，不自动建立事实关系。超长列表按能容纳的完整成员处理，不用任意文本前缀伪装完整集合。
4. 在同一选择器内按问题输出的软覆盖增量/实际序列化成本选材。需求来自原问题、已有主体/时间约束及原文可见的目录或成员提示；各输出等权，提示缺失不排除原文。纯问句仍可提供上下文，但不算已满足事实需求；混合话语复用既有陈述范围。覆盖增量相同时继续比较直接语义/词面检索排名与成本，不因词汇不同就退回僵硬的来源顺序；实体扩展、目录扫描的局部名次不冒充问题相关性。一次有界局部交换可替换一至两个低贡献单元，仍使用同一目标与预算。完整原文单元与附带邻居的上下文是互斥变体，不成为另一条检索链；输入顺序、不同角色/日期/事件及原文坐标保留，只去重已可见的原文区间。软覆盖不证明事实真值或集合完整，也不参与拒答阈值。
5. 构造读取单元和最终选择使用同一消费者提供的序列化成本。直接 synthesis 复用生成端的来源 renderer、紧凑 JSON 和时间引用判定，不再把重复 claim、未发送的元数据或另一种 JSON 空白格式计入预算。构造时用最大来源编号保守计费，最终选择用实际编号；来源目录的固定外壳预留 13 字符，非空目录的总字符数等于外壳加各来源条目及分隔符。只做一次最终预算选择，不再先按短摘要截断、再追加独立 closure 预算。检索 top_k 仍控制公开 search 和原检索记忆数量，但不再直接限制可回读原文单元数；删除内部固定 20 单元截止，阅读由同一字符预算及现有公开来源契约 120 上限约束。原文补检索 candidate_limit 不变；融合池还包含结构化候选，不能把 120 误报为融合池总数。删除独立 `raw_limit` / `grounding_max_raw_sources` 配额，原文与压缩命中竞争同一预算。直接 synthesis 的证据上限沿用原最终 closure 上限 `min(可用证据预算, answer_limit*0.72)`，不是增加一份预算。

这里使用的是可复现的预算选择，不是训练好的 entailment verifier，也不具有一般次模最优界。`selection_decisions` 记录候选身份、读取变体、排序、软覆盖增量、最终来源编号与序列化成本及未选原因。`reasoning.evidence_catalog` 记录实际生成目录的 SHA-256、字符数与有序编号；生成和校验沿用同一最终来源顺序。`context_serialized_chars` 是准确的来源字符计量，旧 `context_tokens_estimate` 仅作为兼容别名保留，`context_budget_unit` 明示其单位。来源字符数可精确核对，但不等于完整提示词长度、供应商实际计费 token 或费用；`final_missing_info` 仍只是词法线索，不单独触发“没有事实”的结论。

`request_fields_available/selected` 分别统计候选和最终来源中可见的请求目录字段，按输出、主体、关系去重；`binding_units_available/selected` 仍只统计原有成员身份。成员数为零不表示没有字段覆盖；两类计数都不证明语义匹配为真或答案集合已经完整，也不触发拒答。

可选的原文向量投影使用独立 namespace，防止被压缩记忆投影同步清理；仍以模型、编码策略和内容哈希缓存。owner 删除覆盖两类 namespace，写入受 generation fence 保护。

## 生成与生命周期

回答契约明确允许有来源的日历运算、计数和显式关系推导；对推断问题要求给出有前提的限定结论，对真正缺失的必要事实继续拒答。计划、助手建议和推断不能成为已观察事实。

移除了旧的 `what did X research` / `when did X go` 特定问法直答。这些规则曾依赖相似度阈值，不能作为通用可信回答算法。

原文读取受会话权限和记忆生命周期约束；`plan.as_of` 约束事实有效期，不把来源发言时间当作历史阅读截止时间。被撤回、过期、未确认或作用域不适用的记忆所引用事件，不能通过原文补检索绕过隔离。同一被隔离事件中的独立有效引用仍可按授权范围读取，不能借此恢复整段原文。

生命周期隔离以每个 memory_id 的最新版本为准。被消费的抽取候选与其已生效替代版本可以共享 quote；在检索已确认有效且已授权的记忆中，该精确 quote 仍可使用，但不能据此恢复整段被隔离的原文。HTTP 生命周期回归覆盖了晋升、替代、撤回和缓存失效的这一边界。

回答后保留既有版本/时间快照复验。`GroundingTrace` 随答案回执保存初始/最终来源数、补检索查询、候选数、选择决定、归属冲突、时间推导数与序列化预算。长期晋升与合并保留同一引用契约，来源去重包含 `start/end`；长期摘要仍是可重建视图，不成为新证据。

## 当前设置和消融

```dotenv
MEMORY_GROUNDING_ENABLED=true
MEMORY_GROUNDING_SEMANTIC=false
```

`evidence_grounding_enabled` 控制旧 plain-answer 接口的证据恢复；直接 synthesis 始终使用原文来源契约。`grounding_semantic_enabled=True` 启用已有原文语义补检索。没有独立原文条数开关，也没有新增生成模型调用；输入长度和实际费用仍需分别测量。

### 真实模型组件对照

`experiments/verify_grounding_live.py` 使用相同的人工设定有损压缩、相同原始发言、确定性检索计划和 DeepSeek 模型，只切换证据层。6 个合成案例交替执行两种设置。它是受控组件实验，不是公开 benchmark，也没有把固定规划器称为真实 LLM 规划。

| 指标 | 关闭证据层 | 开启证据层 |
|---|---:|---:|
| 规则检查通过 | 1/6 | 6/6 |
| 实际模型请求 | 6 | 6 |
| 输入 tokens | 3884 | 5991 |
| 输出 tokens | 176 | 134 |
| 保守计费（元） | 0.0110112 | 0.0156648 |

该历史组件实验修复了三类来源时间问题、遗漏材料和说话者错配；未知供应商在两组均保持拒答。增加来源令输入 tokens 上升，实验没有证明“更准同时更省”。原始结果：`result/grounding_live_ablation.json`。该阶段付费调用约 ¥0.026676，累计费用上界约 ¥17.5376792，未超过当时授权 ¥18。

### 原 100 题证据回放

旧临时数据库已删除，因此只在 quote 与原始 turn 唯一匹配时重建来源；不匹配或多义匹配保留为未解析。按这一统一重建规则，至少命中一条 gold evidence 从 91/100 到 94/100，全部命中从 85/100 到 88/100，没有原先命中题变成未命中题。它不是新回答准确率，也不能直接和以前不同匹配规则得到的 88/100 混用。

原始数据：`result/grounding_source_replay.json`；脚本：`experiments/replay_grounding_sources.py`。

### 跨样本/数据集的局部检索检查

- 原 100 题之外的 44 道 LoCoMo 早期会话题：原文 BM25 单独 Recall@3 约 43.2%，全部 evidence 命中 19/44。
- 同样 44 题的原文 Qwen3+BM25 RRF 消融：约 40.9%，全部命中 18/44。因此不把该通道设为默认“优化”。
- LongMemEval-S 按问题 ID 哈希固定抽取 50 个完整 haystack：原文 BM25 的会话级 Recall@3 约 73%，全部证据会话命中 27/50。检索输入不含 `has_answer` 或官方 question_type。

这些是历史独立原文通道的组件检查，未给它压缩记忆，不生成答案。LoCoMo 的评分单位是 turn，LongMemEval 是 session，不能直接横比。44 题已经用于当时的消融观察，后续不能再宣称它完全未参与开发。

## 尚未证明的内容和下一轮验收

1. 上述 6/6 是历史组件实验，不能替换完整 QA 得分；65/100 也不能标注为当前版本成绩。本轮固定规划离线回放没有生成新答案，不能据此报告 Accuracy/F1 提升。
2. 真正的跨数据集 QA 泛化、复杂隐含指代、常识组合与答案忠实度没有被规则完整解决。
3. 显式 `events` 权限已经允许检索指定历史会话中未被抽取的发言；只有 `quotes` 权限时仍不能恢复未获授权的细节。信息可访问、被选入输入和被正确回答是三个不同的验收环节。
4. 原文扫描当前是线性扫描；向量投影可缓存，仍需对大历史测量成本与 P95。
5. 下一轮应冻结算法参数，使用未调参的 LoCoMo 对话和 LongMemEval-S，分别比较时间层、原文回退、主体核验的 on/off；报告原文证据覆盖、回答正确率、拒答率、主体错配率及 token/延迟。任何修复之后的同题分数只能作为开发结果。

论文应检验：在统一实验配置与预算下，结构化定位、原文读取和可审计的确定性检查，能否以更少的模型调用与 token 保持或提高答案质量。需通过完整双系统 QA、逐题审计和组件消融支撑，不能用来源覆盖率代替答案质量。
