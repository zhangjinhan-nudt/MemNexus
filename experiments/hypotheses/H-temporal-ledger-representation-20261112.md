# 预注册：时间账本的表示修正（2026-11-12）

> 目的：把时间账本从「文本里的日期清单」修正为「可比较的时间区间」，并让校验层消费主链路的推导。
> 本文件在**执行前**写定假设、判据与回滚条件，避免事后解释。
> 关联：`result/STABLE_FAILURE_DIAGNOSIS_20261112.md`、`result/LME_OPTIMIZATION_RESULTS_20261112.md`

## 0. 一句话

只做两件**可独立判定正确性**的事，暂缓一件只能靠 benchmark 判定的事。

| | 改动 | 性质 | 是否本轮做 |
|---|---|---|---|
| A | 校验层消费主链路 `event_graph.derivations` | 修 bug（同一事实两处计算） | **做** |
| B | 精度感知的区间比较（month/week 转区间，不重叠才判先后） | 数学正确性（区间代数） | **做** |
| C | 账本条目带实体主语（NER/候选实体绑定） | 启发式增强 | **暂缓** |

## 1. 为什么是这两件，不是三件

### A 是 bug，不是能力

同一批证据在两处各算一次：主链路 `grounding` 产出 `event_graph.derivations`，校验层 `_unique_interval_length` 又用 `validate_table` 收到的 `sources` 重建一次图。两者输入不同（落盘的 `retrieved_sources` 是 `lossless_restatement`，`synthesize` 收到的是 `grounded.sources`），已实测出现「离线算得出 28 days、线上算不出」。

一个系统里同一个量有两个来源，且可能不一致——这是缺陷，与数据集无关。判据也是内部的：**改后同一题的差值只能有一个来源**。

### B 是逻辑错误，两个方向同时错

当前代码在月精度上：

- **过保守**：`_difference_allowed` 排除 `interval_month@…`，于是「一个月前」与「两周前」明明可判先后，却判为不可比（phone 题）。
- **过激进**：`interval_start` 被当作事件时点参与相减（`two weeks ago` 的起点被当成事件日期）。

两个相反方向的错误同时存在，说明缺的是表示（区间），不是阈值。区间代数给出唯一正确判据：**两个区间不重叠才能确定先后**，重叠则不确定，必须不判。

这一条不需要 benchmark 来证明对错，可以用穷举测试判定（见 §3）。

### C 才是「为适应题目而改」

`Rachel vs Alex` 的失败，本质是实体识别失败（Olivia 的生日被当成 Rachel 的）。补主语需要 NER 或启发式候选绑定，**错误率本身不可控**：在 LoCoMo 的多实体对话里可能制造新的错绑，而那里有 22 题会受影响。

证据量也不够：temporal 仅 9 题、差异 3 题，无法排除过拟合。**故暂缓，等更大样本，且先只做「问题显式给出候选实体」的保守版本。**

## 2. 影响面实测（不是估计）

| 范围 | 数值 | 来源 |
|---|---|---|
| LoCoMo 有账本的题 | 30 / 1000 | 离线重建，`t5` 的 `retrieved_sources` |
| 其中账本含 ≥2 种精度 | **22 题（73%）** | 同上 |
| LoCoMo `X or Y + first` 结构（C 的影响面） | 1 题 | 静态枚举 1540 题 |
| LME 有唯一差值的题 | 4 / 60 | 同上 |

**修正记录**：此前称「LoCoMo 影响面仅 1 题」，那只对 C 成立；B 影响 22 题。本文件以此为准。

## 3. 阶段与判据

### S0 准备（零成本，不调模型）

1. 写合成测试 `tests/test_interval_algebra.py`：给定两个区间，断言关系判定。
   必须覆盖：同月不同日、相邻月、跨年、month 与 day 混合、完全相同、包含关系、week 桶边界。
   判据：**全部通过才算 S1 前置条件成立**。这个测试不依赖模型、不依赖额度，可穷举。
2. 冻结基线：LoCoMo 用 `e6_full_cap2_20261110`（macro 50.86），LME 用 `t3c/t4b/t4d`（配对均值）。
3. 写定回滚条件（见 §5）。

### S1 校验层消费主链路推导（A）

改动：

- `validate_table(..., derivations: list[dict] | None = None)`，优先用它，缺失时回退重建（保持向后兼容）。
- `providers.synthesize(..., derivations=None)` 透传。
- `runtime.answer` 两处调用传 `event_graph.derivations`。

验证：

| 项 | 方法 | 判据 |
|---|---|---|
| 单元 | 传入 derivations 时不再重建图（monkeypatch 计数） | 重建次数 = 0 |
| 功能 | LME 60 题 ×2 次 | guitar（`b29f3365`）2/2 转正；temporal ≥ 5/9 |
| 不回归 | LoCoMo 1000 ×1 次 | 该改动在 LoCoMo **零触发**（`_POINT_OFFSET` 命中 0 题，已静态枚举），故只需 1 次排除意外副作用；判据 \|Δmacro\| < 1.5pt |

成本：LME ¥2.2 + LoCoMo ¥20.7 ≈ **¥23**，约 20 分钟。

回滚条件：guitar 未转正，或 LoCoMo \|Δ\| ≥ 1.5pt。

### S2 精度感知比较（B）

改动：

- `_anchored_dates` 输出 `(lo, hi, expression, precision)`，month = 整月，week = 周一至周日，day = 单点。
- `_difference_allowed` 改为区间判据：`lo_a > hi_b` 或 `lo_b > hi_a` 才可判先后；重叠则返回不可判。
- 差值只在**同类精确端点**上算（day↔day、同锚 week↔week），区间比较只用于序关系。

验证分两级，先便宜后贵：

| 级 | 样本 | 目的 | 判据 | 成本 |
|---|---|---|---:|---:|
| S2-a | 定向 cohort：22 题受影响 + 22 题随机对照 | 检测**局部退化** | 受影响 22 题 F1 不下降；对照 22 题 \|Δ\| < 6pt | ¥1 |
| S2-b | LoCoMo 1000 ×3 | 检测**整体退化** | macro ≥ 基线均值 −1.0pt 且 temporal ≥ −2.0pt | ¥62 |
| S2-c | LME 60 ×3 | 收益 | temporal ≥ 6/9（当前 5/9）；phone 至少 2/3 转正 | ¥3.3 |

S2-a 的作用：22 题若退化 3 题，子集 F1 约掉 6.8pt，单次即可检出；全量 macro 只掉 0.2pt，会被噪声吞掉。**先用敏感的小样本筛，再用全量确认**。

### S3（本轮不做）实体主语

留到有 ≥20 题量级的多实体时间题时再做，且先只绑定「问题里显式出现的候选实体」，并先离线量错绑率。

## 4. 功效说明（必须与结果同报）

- LoCoMo macro 的 run-to-run SD ≈ **1.4pt**（同代码两次差 −1.43，实测）。
- R=3 的均值标准误 ≈ 0.8pt ⇒ 只能排除**大于约 2.5pt** 的退化，**不能证明「完全不变」**。
- 因此 LoCoMo 结论只能写成「差异在噪声内 / 超出噪声」，不得写成「无影响」或「提升」。
- LME 60 题：3 题变化 = 5pt 总分、33pt temporal 分项。故 LME 判据用 **temporal 分项 + 逐题翻转**，不用总准确率。

## 5. 回滚与归因纪律

1. 一次只进一项（S1 完成并记录后，才动 S2）。
2. 每项留独立 commit 与运行目录，禁止混跑（此前混版本曾损失约 ¥13）。
3. 任一判据不通过即回滚该项，**不接受「LME 涨了就保留」**。
4. 若 S2 的 S2-b 与 S2-a 结论冲突，以 S2-a 的局部证据为准并复跑 S2-b——局部样本对退化更敏感。

## 7. 已知限制

1. 三项改动的**净收益上限有限**：只涉及 LME 3 题（占 53 配对题的 5.7%）。
2. B 的收益依赖「账本里两个区间确实对应问句的两个实体」——这仍需要 C 才能完全解决。所以 B 单独做，可能只让 phone 类转正，guitar 仍取决于 A 的兜底是否真正生效。
3. 若 S1 的 guitar 仍未转正，说明「校验层自建图」不是唯一原因，须停下重新定位，**不得继续叠加改动**。
