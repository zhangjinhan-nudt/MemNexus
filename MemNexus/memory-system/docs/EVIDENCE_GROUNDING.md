# 证据恢复、时间推导与主体核验：设计和验证

日期：2026-10-12。本文描述已实现代码及其边界，不把组件检查写成新的 LoCoMo 准确率。

## 研究假设和完成标准

原 100 题实验中 MemNexus 为 65/100，SimpleMem 为 82/100。时间类差距最大；多道错题已检到原始证据，却因缺少来源日期、主体信息或必要细节而拒答。本轮检验的假设是：压缩表示适合定位信息，但回答还需要从原始来源恢复必要的上下文，并以可检查的推导连接证据与答案。

四个问题分别对应可验收的目标：

| 问题 | 代码目标 | 本轮可验证的范围 |
|---|---|---|
| 时间推算不足 | 从来源时间推导带精度的日期区间 | 闰年、跨年、月份、周末、星期、时区边界、有歧义表达不造日期 |
| 有证据仍拒答 | 将来源和可复验推导传入生成器，区分缺证据与需要推导 | 同输入的真实模型组件对照；尚非完整 QA 保留集验收 |
| 证据覆盖不全 | 原始事件补检索与压缩检索合并，最多一轮、受字符预算约束 | 原 100 题源证据回放及另两组公开数据的局部检索检查 |
| 压缩或归属损失 | 原始文本可恢复；时间、说话者由源事件给出；冲突时回到原文 | 混合陈述/问句、主体错配、原文缺失细节、跨会话和撤回边界 |

这不是对所有数据集的正确性保证。日期语言理解、指代消解和最终生成仍有无法由单元测试证明的语义误差；必须保留独立 QA 验证这一关。

## 表示与推理边界

### 结构化问题路由与 typed negative gate

回答阶段现在在来源恢复之后增加一个无模型的结构化层（`reasoning.py`）。它从问题识别 `fact`、`temporal`、`relation`、`causal`、`set`、`count`、`inference` 和 `adversarial` 八种类型，并将复杂关系、集合、计数、因果和推断问题标记为 `recall_first`。这个标记只改变候选召回预算，不能绕过作用域、生命周期或证据检查。

`EventGraph.from_hits()` 使用已经授权的 `Hit.metadata.source_events` 和压缩记忆字段构建小型事件图，保存主体、谓词、值、事件类型、状态、来源编号和实体共享边。图上只执行冻结的确定性推理：来源时间表达式展示、固定城市—国家关系、事件集合计数和来源连接。推理结果始终带来源编号，不被当成新的事实来源。

对抗问题在生成前经过 `typed_negative_gate()`：候选证据必须同时满足主体、对象类型和题目时间约束。没有候选满足全部约束时，系统直接返回 `Not mentioned in the conversation.`，不再让模型把另一个主体、对象类型或时间段的事实迁移成答案。这个 gate 只对明确的选择/未提及问题启用；普通问题仍由证据约束的回答模型处理。

复杂问题会把事件图的紧凑摘要和确定性推导放入回答提示词；提示词预算先为任务契约和近期对话留出空间，再截断图摘要。图上下文和 gate 状态写入 `AnswerResponse.reasoning`，可用于消融和错误归因。

`Event` 新增 `speaker` 和 `source_utc_offset_minutes`。原始时间先保留来源 UTC 偏移，再按既有规范储存 UTC 时间。回答阶段重新使用来源当地日历日期，避免 UTC 跨日引入错误。未提供时区的历史数据不能推断时区；导入器必须声明其假设。

候选抽取不负责生成这些元数据。服务根据 evidence 的 `turn_id/event_index/quote` 回查权威原始 turn，并验证 quote 是逐字子串。保存原文片段偏移、原始说话者、role、时间、推导表达式和规则名称。跨会话来源只展开已经授权的 quote；当前会话的短事件可展开其完整原句，以保留主体和指代上下文。

压缩记忆中的字段仍是检索提示。对于“原说话者是甲，第一人称原话却被压缩成乙”的可确定冲突，回答上下文使用原文替换争议摘要，并记录 `attribution_conflicts`。不尝试凭词法规则证明所有第三人称或隐含指代正确。

## 时间推导

`temporal.py` 产出半开区间 `[start, end_exclusive)`，保留 `precision` 和来源表达式位置。支持绝对 ISO 日期、today/yesterday/tomorrow、last/this/next 年月周、last weekend、前后指定星期、明确 N 个单位 ago，以及部分中文对应表达。

- “last year”只给年区间，不编造月日。
- “next month”保留月精度；12 月正确跨到下一年。
- “last weekend”采用上一 ISO 周末；“last Saturday”采用严格前一个星期六。这些是显式约定，不声称覆盖全部口语方言。
- “已有三年”没有被强制变成购买/领养日期；需要语义事件关系才能推出具体事件。
- “几天前”、无时间锚点、引语内部可能具有不同参照时间的相对表达不生成确定日期。
- `occurred_at`、入库时间 `recorded_at`、事实有效期 `valid_from/valid_to` 不混用。

每条时间结果只是对来源表达式的日历解释，不自动证明它对应了用户所问事件。

## 一轮补检索和预算内证据选择

原始向量/FTS/符号检索保持不变。新层位于检索后、最终回答前：

1. 核对压缩来源，恢复必要原文、时间和说话者。
2. 若词法槽位覆盖不足、时间问题需要锚点、存在归属冲突或 query 内容覆盖较弱，启动最多一轮原文补检索。
3. 主问题加最多 3 条缺失信息形成补检索输入；不传 gold answer、gold evidence 或数据集类别。
4. 默认使用 BM25。BM25+Qwen3 倒数排名融合是独立消融开关，RRF 常数固定 60；本轮没有改善局部召回，所以默认关闭此额外通道。压缩记忆原有 Qwen3 语义检索不受此开关影响。
5. 压缩候选与原文候选按相关性、新增查询词项覆盖和 Jaccard 冗余惩罚进行贪心选择。默认最多 3 条原文、20 条总来源，候选上限 120；字符预算不超过 `min(prompt_token_limit/2, retrieval_token_limit*2)`。

这里使用的是可复现的启发式预算选择，不是训练好的 entailment verifier，也不具有一般次模最优界。覆盖分数和余弦分数不解释为事实正确概率。`final_missing_info` 是词法线索，不能单独触发“没有事实”的结论。

可选的原文向量投影使用独立 namespace，防止被压缩记忆投影同步清理；仍以模型、编码策略和内容哈希缓存。owner 删除覆盖两类 namespace，写入受 generation fence 保护。

## 生成与生命周期

回答契约明确允许有来源的日历运算、计数和显式关系推导；对推断问题要求给出有前提的限定结论，对真正缺失的必要事实继续拒答。计划、助手建议和推断不能成为已观察事实。

移除了旧的 `what did X research` / `when did X go` 特定问法直答。这些规则曾依赖相似度阈值，不能作为通用可信回答算法。

原文补检索受当前会话、历史时点和记忆生命周期约束。被撤回、过期、未确认或作用域不适用的记忆所引用的源事件，保守地从补检索、来源展开和近期对话中排除。这个事件级隔离可能同时排除同一事件中的其他有效事实，是安全与召回的明确取舍；未来可改为经过验证的 span 级撤回。

生命周期隔离以每个 memory_id 的最新版本为准。被消费的抽取候选与其已生效替代版本可以共享 quote；在检索已确认有效且已授权的记忆中，该精确 quote 仍可使用，但不能据此恢复整段被隔离的原文。HTTP 生命周期回归覆盖了晋升、替代、撤回和缓存失效的这一边界。

回答后保留既有版本/时间快照复验。`GroundingTrace` 随答案回执保存：初始/最终来源数、补检索轮数、查询、候选数、覆盖变化、归属冲突、时间推导数与字符预算。日志不把这些字段伪装为语义证明。

## 当前设置和消融

```dotenv
MEMORY_GROUNDING_ENABLED=true
MEMORY_GROUNDING_RAW_LIMIT=3
MEMORY_GROUNDING_SEMANTIC=false
```

`Settings(evidence_grounding_enabled=False)` 关闭新层。`grounding_semantic_enabled=True` 仅用于原文语义补检索消融。新层不额外调用抽取/规划/验证 LLM；必要证据会增加输入长度，不能预先声称 token 总量下降。

## 已完成的验证及结果

工程回归全套 252 项通过；其中 `test_evidence_grounding.py` 的 30 项检查覆盖新链路，包括时区跨日、闰日、周/月/年精度、混合发言、跨会话来源最小展开、撤回隔离、owner 删除期间的原文向量回填屏障以及缓存复用。Ruff 检查通过。两个旧的毫秒级时间竞态测试改用固定时钟/注入 provider timeout，验证的事务边界保持不变。

### 真实模型组件对照

`experiments/verify_grounding_live.py` 使用相同的人工设定有损压缩、相同原始发言、确定性检索计划和 DeepSeek 模型，只切换证据层。6 个合成案例交替执行两种设置。它是受控组件实验，不是公开 benchmark，也没有把固定规划器称为真实 LLM 规划。

| 指标 | 关闭证据层 | 开启证据层 |
|---|---:|---:|
| 规则检查通过 | 1/6 | 6/6 |
| 实际模型请求 | 6 | 6 |
| 输入 tokens | 3884 | 5991 |
| 输出 tokens | 176 | 134 |
| 保守计费（元） | 0.0110112 | 0.0156648 |

修复了三类来源时间问题、遗漏材料和说话者错配；未知供应商在两组均保持拒答。增加来源令输入 tokens 上升，实验没有证明“更准同时更省”。原始结果：`result/grounding_live_ablation.json`。本轮全部付费调用约 ¥0.026676，累计费用上界约 ¥17.5376792，未超过授权 ¥18。

### 原 100 题证据回放

旧临时数据库已删除，因此只在 quote 与原始 turn 唯一匹配时重建来源；不匹配或多义匹配保留为未解析。按这一统一重建规则，至少命中一条 gold evidence 从 91/100 到 94/100，全部命中从 85/100 到 88/100，没有原先命中题变成未命中题。它不是新回答准确率，也不能直接和以前不同匹配规则得到的 88/100 混用。

原始数据：`result/grounding_source_replay.json`；脚本：`experiments/replay_grounding_sources.py`。

### 跨样本/数据集的局部检索检查

- 原 100 题之外的 44 道 LoCoMo 早期会话题：原文 BM25 单独 Recall@3 约 43.2%，全部 evidence 命中 19/44。
- 同样 44 题的原文 Qwen3+BM25 RRF 消融：约 40.9%，全部命中 18/44。因此不把该通道设为默认“优化”。
- LongMemEval-S 按问题 ID 哈希固定抽取 50 个完整 haystack：原文 BM25 的会话级 Recall@3 约 73%，全部证据会话命中 27/50。检索输入不含 `has_answer` 或官方 question_type。

这些是独立原文通道的组件检查，未给它压缩记忆，不生成答案。LoCoMo 的评分单位是 turn，LongMemEval 是 session，不能直接横比。44 题已经用于本轮消融观察，后续不能再宣称它完全未参与开发。

## 尚未证明的内容和下一轮验收

1. 本轮未重新付费跑完整 100 题双系统 QA；65/100 仍是最后一次完整 MemNexus 测量，不能替换为 6/6 组件得分。
2. 真正的跨数据集 QA 泛化、复杂隐含指代、常识组合与答案忠实度没有被规则完整解决。
3. 原文回退只检索当前会话；跨会话只展开已授权记忆引用。长期压缩完全漏掉且没有可达引用的事实仍需独立、带作用域的原文索引。
4. 原文扫描当前是线性扫描；向量投影可缓存，仍需对大历史测量成本与 P95。
5. 下一轮应冻结算法参数，使用未调参的 LoCoMo 对话和 LongMemEval-S，分别比较时间层、原文回退、主体核验的 on/off；报告原文证据覆盖、回答正确率、拒答率、主体错配率及 token/延迟。任何修复之后的同题分数只能作为开发结果。

面向 ICAPS，适合研究的可检验问题是：在固定预算下，显式来源恢复与可审计推导能否降低错误状态输入及过时行动；须另接规划器并测执行结果。当前代码不是完整形式化证明系统，也不构成已证实的新颖算法或中稿保证。
