# 集合记忆与可检查答案：实现说明

本次采用一个新的领域模块 `composition.py`，复用现有模型、SQLite、运行时和证据接口；没有引入图数据库、独立 verifier 服务或新的第三方依赖。

## 数据契约

`Candidate/Memory.semantics` 区分 `one / many / unknown`。旧记录缺省为 `unknown`，不根据一个含逗号的字符串猜测集合成员。

- `many` 用 `members` 保存原子值及各自的原文引用。每个成员都经原有来源校验，不能借父记忆的合法引用夹带无来源成员。
- `assert/add` 增加成员，`remove` 移除指定成员，`replace_set` 仅表达有原文依据的完整集合替换，也可表示明确空集。操作日志保留；撤回错误的移除/替换后，下一次查询重新计算集合。
- `one` 在同一作用域、属性及事件限定下保留原有冲突审核。`unknown` 的异值保留并存，不静默覆盖，不默认判成冲突。
- `event_key` 是事件限定/话题；`event_identity` 才是某次事件身份。实体 `identity`、事件身份和来源 utterance ID 分开。无法可靠判定身份时保留空值，不能以节点数或同名字符串冒充精确计数。

抽取仍用既有 `extract` 调用。相对时间、来源 speaker 和原始内容继续由现有系统保留。新字段不把模型的语义判断升级成形式化事实证明。

## 写入时关系索引

SQLite `fact_projection` 按 owner、subject、predicate、event_key 建立索引，并引用权威记忆 ID/version。每次 `_save_memory` 在同一事务更新投影，查询后仍应用现有作用域、状态和有效时间过滤。删除 owner 同时删除该投影。

数据库 `user_version=2`，旧数据库首次打开时从原有 JSON 记录重建索引，原文和旧记忆不被重写。该表是可重建关系投影，不是第二个事实库，也不是声称已经实现通用知识图谱。

## 查询与回答

`CollectionQuery` 明确主体、谓词、操作、计数单位、事件限定、额外语义条件及允许的断言类型。现有 planner 返回该契约；可识别的集合/计数路由使用必填 schema，避免生成一个只有“列完整”提示的空计划。

现阶段支持 union、按主体 group、跨主体 intersection、distinct count，以及明确排除值。交集项保存双方前提，计数保存成员及身份。没有实现任意图路径查询、通用因果推理或自动事件共指解析。

两条互斥路径：

1. **类型已明确且条件可直接执行**：先枚举授权关系分区，再折叠集合操作，执行查询并直接渲染；不调用答案生成模型。初始 top-k 不裁掉该分区已确认的成员；关系分区最多处理 `min(max_candidates, 120)` 条记忆，预算不足会留痕。来源回执相应支持最多 120 条。
2. **旧记忆、类别投影或额外语义条件**：沿用证据回查，用一次结构化 `compose` 调用替代自由文本 answer。每个送入的来源都必须有处理记录；候选逐项绑定原文，记录接受、拒绝、未知及语义归一映射。代码随后执行相同查询算子并渲染。复用原有最多一次结构化修复，真实 provider attempt 应从 usage ledger 读取。

不同来源措辞可映射到查询所需的同一概念，但原始值、原文和模型理由均保留。语义归一仍可能出错，不能把字符串比较或模型给出的同义标签称为语义证明。

## AnswerIR 与完整性边界

`reasoning.answer_ir` 保存查询、快照、候选原子项、最终成员、推导规则/前提、排除项、来源处理记录、语义归一以及覆盖状态，随答案回执保存。实验 runner 同时保存 `reasoning`。

覆盖状态明确区分：

- 哪些来源片段被检查，是否有未处理 turn；
- 指定关系索引是否枚举完成，是否预算耗尽；
- 查询运算是否完成、哪些身份或语义仍不确定；
- 最终渲染是否保留全部已确认成员。

`extraction_completeness=not_proven`：抽取了原文不等于原文含义一个不漏。`output_complete=true` 只表示结构化结果已全部渲染，不能当作问答正确率或全语料召回率。

空交集/无命中默认不能证明整段对话不存在。明确的空集合快照可以支持空结果；身份不明不输出精确计数。已识别成员但未完成枚举时，可给有条件的计数下界；原文直接陈述的总数另有 `explicit_total` 规则，不要求虚构所有成员姓名。不同的显式总数不会因相同标签而被去重掉。

旧 typed negative gate 现在记录 `not_found_in_examined_evidence`，不再从不完整子图自动发布全局“未提及”。

## 开关与测量

`MEMORY_COLLECTION_QUERIES=true` 默认开启；设为 false 可对同一记忆快照消融新的回答路径。这不是回滚存储 schema，也不等于复现旧版本全部提示词。

仍需计入建库新字段的输出成本、planner、结构化修复及语义裁决成本。原有 token 预算仍为字符代理，实际费用和 tokens 以 provider usage 为准。当前检索仍有 owner 级快照扫描，不能据此声称大型图查询复杂度已优化。

## 验证

- 工程回归：281 passed，其中新增 19 项集合机制测试；实验 runner 测试 4 passed。
- 修改涉及的源码及测试通过 Ruff 检查。全仓库仍有本次未修改文件的旧风格告警，不计作本次新增问题。
- 真实 DeepSeek 验证：从保存的 LoCoMo 原文抽取并提交 3 条类型化记忆，包含 3 个原子情绪成员；另对 5 道既有开发题固定证据做真实模型复测。
- 复测数据、失败尝试和费用均保留在工作区 `result/collection_architecture_smoke_20261013*.json` 及对应 usage/calls 文件。最终版本另存源码快照，哈希与当前包源码一致。

这次不是独立泛化评测或 SimpleMem 重跑。已看到缺失答案项恢复，也仍有情绪漏项、跨事件混入、目标与修辞性表述混淆及同义项未合并。详见工作区 `result/COLLECTION_ARCHITECTURE_VERIFICATION.md`。后续须固定版本、按对话划分新测试集，分别量化成员 precision/recall、完整无多余项率及端到端成本。
