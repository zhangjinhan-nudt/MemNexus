# 优化实验协议 v2

2026-10-20 重立。适用于 MemNexus × SimpleMem 在 LoCoMo / LongMemEval 上的一切对比。
目的只有一个：让"这次改动到底有没有用"这个问题有唯一答案。

---

## 0. 为什么需要这份协议

以下五条都是实测，不是推测：

| 事实 | 数值 | 后果 |
|---|---|---|
| 同配置连跑三次 150 题 | MN 120 → 114 → 114（±6）；SM 115 → 117 → 116（±1） | 单次运行的题型级涨跌不可读 |
| 逐题翻转 | 对上一轮 14 题，对基线 18 题 | 任何 <18 题的差值都可能是抽签 |
| 建库不可复现 | SimpleMem 代码一字未改，两次运行证据集相同率 **0/150** | 建库是噪声主源 |
| 待测效应 | ±2~4 题 | 噪声是效应的 4~9 倍 |
| 一次改 7 个变量 | plan −32.4%、extract +10.7%、answer +61.3%，**净 +9.2%** | 归因不可能，收益为负 |
| 一次改出崩溃 | `set(source_events)` 遇 `list[dict]`，32 题静默计错 | 89/150 是假数字，白跑 ¥13 |

结论：**变量太多 + 无门禁 + 无配对 = 读数不可用。** 协议就是为了把这三件事钉死。

---

## 1. 三条铁律

**R1 一次只动一个行为变量。**
一个运行里只允许出现一个会改变模型输入或输出行为的改动。测量类基础设施（快照、账本、比较脚本）不计入变量，但必须默认关闭、单独提交、全套测试通过。

**R2 先看崩没崩，再看准不准。**
任何比较的第一条读数必须是 `forced_abstain == 0`。`status=completed` 不代表没崩——上次 32 道题崩在答题阶段，异常被兜底吞掉，最终记成错答，报告照样是 completed。

**R3 只有配对运行才能判显著。**
配对 = 同一冻结记忆库（sha256 相同）+ 同一题组 + 同一配置除待测变量外全同。
不满足就只能记方向，不得写"提升/下降"。

---

## 2. 变量分级：N / L

| 级别 | 定义 | 判据 | 准入 |
|---|---|---|---|
| **N（无损）** | 任何 token 都不离开输入，纯表示/序列化/缓存/日志/单位修正 | 输出语义应逐题不变 | 任何主张下都可做，但**仍需单独一次运行**验证没有副作用 |
| **L（有损）** | 有 token 进入或离开模型输入，或改变检索/拒答决策 | 必然有权衡 | 只能由研究主张裁决，只进消融表，不进默认配置 |

判定口径：**只要改动会让任何一条证据、字段、规则进入或离开提示词，就按 L 处理。**

这条口径来自上次翻车：证据上限 8/12 → 24/30 被当成"顺带的无损改进"塞进同一轮，answer 单次 token 从 2,714 涨到 4,379（+61.3%），把 plan 省下的 32% 全部吃掉。

## 3. 实验单元流程（七步）

1. **预注册**：`experiments/hypotheses/<id>.md` 写清假设、预期符号与量级、机制、判定阈值、回退条件。写完再跑，不许事后补。
2. **测试先行**：新增行为必须有测试，且先看到它红。
3. **冒烟**：单对话 3 题，确认 `forced_abstain=0`、repair 次数没有爆炸。
4. **主运行**：150 题，`--memory-snapshots result/memnexus_snapshots/main`（命中即回放，未命中才建库）。
5. **判定**：`compare_paired_runs.py`，看 McNemar 精确 p 与 token 增幅。
6. **记录**：`ANALYSIS_<date>.md`，必须含配对表、翻转样本、以及"如果没有生效，最可能是哪一步没走到"。
7. **归档**：接受则更新基线；拒绝则 `git checkout --` 该变量，写清否决理由，不许留着"以后再试"。

---

## 4. 判定规则（预注册，不许事后改）

| 条件 | 判定 |
|---|---|
| 任一运行 `forced_abstain > 0` | **INVALID**，不读准确率，先修崩溃 |
| 两侧快照 sha256 不全等 | **UNPAIRED**，只记方向 |
| 净正确数 < 0 | **否决** |
| McNemar p ≥ 0.05 | **不可判定**，不得写"提升" |
| p < 0.05 且 token 增幅 ≤ +2% | **通过** |
| p < 0.05 且 token 增幅 > +2% | **有条件通过**，须由主张裁决，写清牺牲了什么 |
| 连续两次独立主运行同向 | 才可进论文表格 |

150 题配对下，**6 胜 0 负**（p=0.031）是最小的显著模式；4 胜 1 负 p≈0.38，与抛硬币无异。
这个数字要记住：它意味着"多对 2 题"这种收益本质上不可验证，除非效应更大或题量更大。

## 6. 两类允许插队的事

- **纯测量基础设施**：快照冻结、usage 账本、配对比较、确定性校验。不算行为变量，随时可落地，但必须满足：参数为 `None` 时行为与旧版完全一致 + 全套测试通过。
- **修崩溃**：崩溃优先于准确率，允许插队，但必须附回归测试，且修完**重跑该运行**，不得沿用崩过的数字。

同一快照、同一配置、连跑三遍，29 题：

| 指标 | 结果 |
|---|---|
| 答案文本三遍完全一致 | 23/29（79.3%） |
| **证据集三遍完全一致** | **7/29（24.1%）** |

根因已定位到 plan 阶段，不是检索本身：两遍之间 `keywords` 变 23/29、`semantic_queries` 变 22/29、

`temperature=0` 与 `thinking=disabled` 已经设置在 `providers.py::_request`，**这不是配置遗漏，是服务端在 temp=0 下仍非确定**。
即：MemNexus 把检索决策交给自由文本生成器，plan 的采样抖动被放大成证据集抖动；SimpleMem 的检索查询固定为原问题，所以它的噪声只剩生成级（±1 题）。

### 因此

单次 150 题运行的差值**不可判读**的范围比原先估计更大：不止 ±14~18（含建库噪声），
即便冻结建库，仍有约 3/4 的题目在两次运行中拿到不同证据集。任何 A/B 必须满足其一：
① R 次重复、逐题取均值、配对检验；② 先降低 plan 抖动（冻结 plan 或规则化检索查询），再谈单次读数。

## 9. 指标口径（锁定，2026-10-20 22:30）

依据 SimpleMem 原论文（资料库 `refer` 第 16 篇，§3.1 + Tables 1/3 + 附录 A.4）。
**唯一实现**：`experiments/paper_protocol.py`。任何报告、看板、A/B 判定都必须从该模块取数。

### 9.1 LoCoMo 报什么

四个指标，缺一不可：

| 指标 | 定义 | 实现 |
|---|---|---|
| F1 | LoCoMo 官方 F1（去冠词/标点、Porter 词干） | `f1_of()` |
| BLEU-1 | 同规范化的 clipped unigram precision + brevity penalty | `bleu1_of()` |
| Adversarial Success Rate | 对抗题拒答诱饵的比例 | `adversarial_success()` |
| Token Cost | 问答阶段每题输入＋输出 tokens | `paper_table()` |

**Average 是四类推理题（MultiHop / Temporal / OpenDomain / SingleHop）的等权算术平均，不含对抗题。**
论文 Table 1 只有这四列、没有对抗列；对抗以 `Adversarial SR` 单独报告。
验证方式：(43.46+58.62+19.76+51.12)/4 = 43.24，即论文 SimpleMem 的 Average。

### 9.2 不许做的事

- **不许**把对抗题算进 Average（会把 MN 抬高约 3 个点，历史上正是这么误读的）。
- **不许**用逐题平均代替等权平均（题量分布不同，结论会翻转：实测同一批数据三种算法得出"打平 / 落后 3.6 / 落后 7.9"三个结论）。
- **不许**把 LLM 裁判当 LoCoMo 成绩。论文的裁判（附录 A.4）只用于 LongMemEval-S。
- **不许**在非配对子集上比较。两系统完成题数不同时（崩溃/续跑），必须取交集。
- **不许**修改 A.4 判分措辞。它是刻意宽松的（"touches on the same topic 即 CORRECT"），收紧会改变测量结果。
