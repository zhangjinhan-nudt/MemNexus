# ACL 2027：两项最小改动的实施与验证方案

本方案收敛此前设计，限定为现有问答流程的改造。状态：设计完成，尚未实施，未产生新的模型测试结果。日期：2026-10-13。

## 1. 研究问题、范围与预期贡献

研究问题：在相同模型与资源预算下，用可检查的回答操作明确“还缺什么前提”，能否减少长对话问答中的漏项、主体/事件误配与错误拒答？

本轮只做：

1. 统一现有答案表的目标、操作前提、执行和检查。
2. 用执行产生的具体缺口触发一次补检索和增量绑定。

保留现有短/长期存储、抽取、版本、SQLite、embedding和混合检索基础。实体/事件绑定先仅存在于当前请求，不做全历史图重建、数据库迁移、全局实体解析或新模型训练。这样可用相同真实记忆快照隔离问答机制的贡献。

ACL研究叙事聚焦语言理解与证据组合：用户问句中的输出和限定如何映射到证据；多条陈述如何支持一个答案操作；证据缺失与解释错误如何区分。不要将数据库、功能数量或工程测试数作为研究贡献。

相关工作边界：

- [BFR, 2026-10-07](https://arxiv.org/abs/2610.09348v1) 已有需求分解、互补证据选择和预算化补全，主方法使用固定访问日程，也评测状态条件化变体。
- [QGMem, 2026-10-08](https://arxiv.org/abs/2610.11920v1) 已有事件记忆、动态状态轨迹和查询相关局部图。
- [Sufficient Context](https://arxiv.org/abs/2411.06037) 已区分上下文不足和模型未利用上下文。

因此候选贡献是**回答操作的前置条件同时约束生成与补检索**，包括固定语义绑定下的集合/计数一致性和时间端点约束。新颖性及收益仍须与上述方法比较，不能将“充分性”或“事件图”本身视为创新。BFR/QGMem在本次核查时是预印本，不能宣称其结果已被本项目复现。

## 2. 当前基线和不能改变的事实

冻结版本来自`locomo_synthesis_replay_20261013_v4.json`及源码快照。现有开发成绩MemNexus 78/100、SimpleMem 73/100；配对差值+5个百分点，聚类95%区间[-1.18,+11.54]，尚不显著。

成本：MemNexus建库＋问答估算¥7.1531，SimpleMem ¥9.0232；总token分别2,188,644与1,893,271。费用更低不等于token更少。原100题已经用于开发，不能用后续提升证明独立泛化。

本阶段保留现有基线报告，所有新运行另存，不用修改后的错题答案替换历史结果。

## 3. 第一项：在现有类上增加最小契约

### 3.1 输入契约：扩展QueryPlan

在QueryPlan中增加可选的`answer_contract`。由同一次现有planner调用填充，不新增planner调用。

每个用户要求的输出只需：

```
output_id
question_span             # 对应用户问句，不包含答案
operator                  # direct / set / count / time_point / duration
constraints               # 主体、关系、事件限定、as_of、状态
required_inputs           # 必要输入ID及类型
```

设计约束：

- output是不可缺少的用户请求，不能由后续模型改成context。模型可报告unknown/partial，不能悄悄删除。
- prerequisites是获取结果的输入，例如两个时间点；它们不是最终答案。
- 不填gold、预期数量或预期成员；约束须能追溯到问题，推断假设另标。
- 首版不实现任意查询语言、复杂多层DAG或开放式规划。五种操作足以覆盖当前主要失败机制。
- 未支持的开放域推断可使用direct文本值，标明inferred，与陈述事实分开；不能因不支持算子把整个问题强制拒答。
- 保留旧required_info用于兼容和检索，但有新contract时不再作为第二套最终输出依据。

### 3.2 证据绑定：扩展AnswerTable

保留现有slots/values/supports，在操作需要时增加：

- `output_id`及输入引用；
- `subject/relation/event_binding`的短结构及对应支持片段；
- `members`或`time_operands`，计数/时间操作才出现；
- `status`：supported / partial / unknown / conflict；
- `gaps`：缺口代码、对应输入/输出、已绑定线索。

复用已有来源ID、turn/event位置与memory version。请求内部ID不声称是全局实体ID，也不直接写回记忆真值。

模型负责提出自然语言解释，本地程序检查形式、引用、范围和操作前提。主体/关系蕴含不能仅靠“引文中有人名”验证，模型解释不确定时保留unknown。跨句指代可同时引用提问与回应，但问句或assistant建议不能独立建立事实。

### 3.3 五种操作的本地规则

| 操作 | 必要输入 | 本地处理 | 不满足时 |
|---|---|---|---|
| direct | 与所问主体、关系和限定匹配的值及来源 | 检查支持、类型、scope/version；渲染短值 | unknown或明确缺口 |
| set | 同一关系范围内的成员及身份依据 | 仅合并有依据的同一成员，保留来源 | 输出已知成员并标部分状态 |
| count | 与set同构的成员集合，或有明确范围的总数声明 | 去重后计算；禁止与成员无关的自由数字 | 下界或unknown |
| time_point | 对应事件的时间及来源锚点/精度 | 用已有temporal工具归一和按精度表达 | 缺事件/锚点；不伪造日期 |
| duration | 两个角色明确、对象一致的事件时间，或直接时长陈述 | 精确值计算，区间传递不确定性 | 缺端点、身份歧义或范围不确定 |

集合重要限制：扫描完某个索引、预算耗尽、没有新命中，均不证明实际成员穷尽。照片数量是观察子集；明确总数必须有对应量词、主体、范围和时间支持。严格exact_count要求闭合范围；否则保留lower_bound。评测同时统计错误拒答，避免过严规则使质量下降。

时间重要限制：来源中出现日期不意味着是事件发生日；明确发言时间只可用于该相对表达的锚定。不能以过去测试题的gold为依据固定“上周”的唯一解释。

### 3.4 检查结果与错误处理

`check_and_execute(contract, table, sources)`统一返回结果及gap：

```
output_missing
subject_unresolved
relation_or_event_unresolved
member_scope_unknown
time_operand_missing
source_invalid
conflict_unresolved
```

不是所有gap都触发检索：非法来源/格式先走现有一次修复；已选证据中可修正的解释优先本地检查或一次增量绑定；确实缺来源才触发补检索。不要将语义缺口反复当schema错误要求模型重写。

当前negative_gate降为候选约束诊断，统一检查器负责决定候选能否进入答案。不能把未命中候选解释为事实不存在。原有生命周期和scope过滤继续在每次补充前执行。

## 4. 第二项：一次缺口驱动的补检索

### 4.1 流程

```
plan -> 当前候选召回与来源回填 -> synthesize/bind
     -> check_and_execute
        -> ready: render
        -> 有可检索gap且有预算:
             retrieve_gaps -> bind_delta -> check_and_execute -> render
        -> 其他: render支持部分，并记录缺口/停止原因
```

检索完成后模型只绑定新增证据及必要旧绑定，不重写所有已验证值。为保持ID稳定，来源表追加编号；旧引用不可因重排指向另一段文字。更正冲突时保存被替换绑定及其原因。

首版复用当前initial grounding，避免同时改变候选生成和执行机制。在实验中对照同等预算的扩展top-k/固定邻接，防止收益只是额外上下文。若initial grounding已有一次raw fallback，必须单独计为初始阶段工作；新增gap补充一次，禁止把实际三次访问隐瞒为“两次检索”。

### 4.2 gap到检索动作

| gap | 查询构成 | 使用现有能力 |
|---|---|---|
| 主体/代词 | 问题主体＋事件动作＋缺失角色 | entity/lexical/semantic＋小范围邻接 |
| 泛称事件缺细节 | 已绑定事件线索＋所问对象/产物 | 原文查找和后续解释 |
| 时间输入缺失 | 对象＋对应动作＋缺失日期角色 | 原文/时间metadata查找 |
| 成员范围不足 | 主体＋关系族＋增删/归属线索 | 结构化事实候选＋原文 |
| 版本冲突 | 同一主体关系＋所问时点 | 已有版本、有效期、原文更正 |

新查询不含预期答案，不凭模型草稿去搜同样的结论。补充候选必须能关联具体gap；仅同主题或同人名不视为已解决。

### 4.3 选择与停止

初版采用可解释规则，避免训练新policy：优先直接阻塞请求输出的gap，再选缺口覆盖潜力高、重复少、成本低的候选。对于两个来源合用才能成立的前提，允许有界证据对；不能用单条词面收益排掉互补记录。

首版最多2个gap查询，每个最多取4条新候选、去重后最多8条，最终context仍受统一总token预算。它们是待开发验证的默认值，不是论文结论；开发集完成一次小范围敏感性检查后冻结。

停止条件：补充完成一次、没有新增有效来源、预算不足、或必需输出的前提已满足。终止原因显式记录；没有证据不等于反证，预算耗尽不等于事实不存在。

局部范围明确时，已完成操作可直接输出；枚举的全局完整性仍是条件性判断，不从覆盖词数或固定阈值宣称证明。

## 5. 改动规模与成本约束

核心修改集中在五个文件：models.py、synthesis.py、providers.py、grounding.py、runtime.py；settings.py仅增加预算配置。复用composition.py与temporal.py的可用函数，只有发现确切缺口时才作小改。测试放入既有测试目录。

不新增独立服务或永久事实库。`QueryContract`嵌在现有QueryPlan，gaps嵌在AnswerTable；计数、时间函数采用明确输入输出接口即可，无需构建通用DSL或规划框架。

正常问题仍是一次planner＋一次binder，两次常规模型调用。缺口问题最多增加一次binder；整个回答最多允许一次格式/来源修复，故实际provider attempts上限可为4，不能把修复漏计。达到预算时返回支持状态，不偷偷切模型或使用gold回退。

预算应对实际发往provider的消息计量，包含schema、原文、绑定、输出预留和重试。统一答案检查应替换重复解释，不在已有两次调用外额外固定添加verifier。预计收益是更少遗漏和更有用的context；是否降低总体成本必须测量。

系统比较包含建库、问答、失败和修复；可复用原建库时仍将其成本计入工作负载。主评测关闭答案缓存，冷/热缓存作为效率消融另列。固定记忆结果与完整独立建库结果分别报告。

## 6. ACL实验问题与最小矩阵

H1：给定相同证据，统一执行是否减少漏项、主体/事件误配和数值不一致，而不是增加拒答？

H2：等调用/token/费用预算下，执行gap驱动的补检索是否比扩大top-k、固定邻接或一般“missing information”补检索更有效？

H3：两个改动的组合收益是否能迁移到未用于开发的对话/数据集，且不高于SimpleMem成本？

H1中的语言绑定仍可能错；仅对固定绑定和完整输入能证明集合/数值操作不变量，不能把它扩张为自然语言正确性保证。

### 6.1 消融设置

| 系统 | 统一执行 | 补检索 |
|---|---|---|
| A（统一实验接口） | 关闭新结果执行，沿用原答案值输出 | 关闭gap补充，沿用初始检索 |
| E | 新机制 | 旧机制 |
| R | 使用同一契约/绑定来生成gap，但最终输出沿用普通生成 | 新gap补充 |
| E+R | 新机制 | 新gap补充 |

四组通过同一契约/绑定接口以便控制中间表示；开启执行表示将检查结果用于约束和计算最终答案，关闭执行时保留gap诊断所需信息、沿用原答案值生成。原78/100冻结版本作为额外历史对照，不能把它与接口已改变的A混同。R与E+R共享需求解析和gap获取的调用开销，避免把“检索消融”免费赠予额外LLM能力。R仅禁用新本地结果约束与确定性运算，不删除补检索必需的中间状态。额外比较同样增加一次模型调用但只给更宽top-k的控制组；所有新调用计费，不免费赠送最终writer。

主要外部基线为SimpleMem，另加Raw-turn RAG；ACL投稿前至少加入BFR的可复现近邻对照。BFR若无法直接运行，机制适配必须明确标识，不能冒充原作者实现。优先这几个对照，不因扩展基线而增加生产系统范围。

### 6.2 数据与评分

- 原100题作为开发回归，全部题都重测，公布修复/退步。已研究过的LoCoMo对话均披露开发暴露，新的题号不自动成为独立测试。
- LongMemEval-S在使用前确定开发/测试或使用其他开发集后整组封存；若曾检查过某部分题目，需记录并排除其独立测试身份。
- 最终报告官方LoCoMo F1/BLEU口径和LongMemEval标准accuracy；本项目语义裁判分数另列。旧100题的固定A/B对抗协议单独说明。
- 固定model/embedding版本、编码、价格、随机顺序、候选池和上限。主模型继续DeepSeek-v4-flash，额外一个backbone作为迁移验证。
- 评测证据标注仅用于事后分析，不能进入planner、gap生成或补检索。原文turn命中与答案蕴含分开评测。
- 问题级配对比较并报告对话/用户聚类置信区间。LoCoMo对话簇少，增加同对话题量不能替代独立样本。
- 统一judge提示、系统名盲化、回答顺序随机；对主体、状态和时间歧义做双方对称的人工复核，保持官方原分数并另报审查结果。

### 6.3 指标

主要：官方回答指标、同预算下正确率、每正确答案全流程成本。

机制：成员precision/recall、主体/事件绑定错误、错误拒答、错误肯定、列表/计数一致性、时间端点及精度错误。

检索：每次补充新增有效来源、经人工抽样确认的gap解决率、补检索触发率、补充后从错到对及从对到错。

效率：建库与问答分列的输入/输出token、真实请求、修复次数、端到端P50/P95和本地处理耗时。统一执行增加的token不能省略，成功题延迟不能代替含失败重试的总耗时。

## 7. 实施顺序及继续/停止条件

1. **2–3个工作日：最小契约与单入口。** 解决所有output降为context、源编号稳定、实际prompt预算等确定问题。固定证据和无模型机制测试通过。
2. **3–4个工作日：集合/时间操作。** 接入成员计数、事件角色和来源条件；对公开开发样本与变形样本同时验证。错误解释记录为binding failure，不能以执行器正确掩盖。
3. **2–3个工作日：一次gap补检索。** 接入已授权候选、去重、增量绑定和停止条件；检查无缺口题不产生额外正常调用。
4. **3–5个工作日：开发回归、消融、冻结。** 主项目回归、原100题开发比较、成本审计与小规模独立样本预检；冻结后进入正式测试。

以上约10–15个工作日是实现与首轮验证估计；完整多基线/跨模型论文实验另需时间与预算。

继续条件：E在固定证据下确有净收益，R在等预算下优于简单扩展，组合在独立数据上稳定，错误拒答和新增语义误配没有抵消收益。具体非劣容忍度、primary endpoint和统计方法在正式测试前注册。

若收益只来自更大的context，收缩算法主张；若只在旧100题提高，停止针对它们继续调参；若重检索频率/成本失控，降低触发范围并在开发集重新验证，不动封存测试集。

## 8. 第一批交付物

统一输出/前提规范、五类算子与gap定义；一个问答执行入口；一次补检索控制器；真实来源/绑定/缺口/成本trace；机制回归和2×2消融脚本。论文以语言理解、证据组合和可复现的质量—成本实验支撑主张。

官方会议范围：[ACL 2027 Call for Papers](https://2027.aclweb.org/calls/main/)。本方案主要对应Question Answering、LLM Agents for NLP、NLP and Symbolic Reasoning及Efficient Methods for NLP。这里的实现规模、验证标准和阶段时间是针对本项目提出的建议，不是会议官方要求。
